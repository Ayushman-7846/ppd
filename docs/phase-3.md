# Phase 3 research evaluation

## Run and authorize reviewers

Run the services from the [setup guide](../README.md) and apply Alembic revisions through `0004` with `alembic upgrade head`. Revision `0003` connects criterion-level evaluation rows to attempts and assignments. Revision `0004` backfills submitted and pending review hashes from their stored input snapshots and scopes assignments to the exact evaluated response text. Review roles are assigned from a trusted backend console after the account registers.

```powershell
cd backend
.venv/Scripts/python.exe -m app.reviewer_roles faculty-reviewer@example.com reviewer
.venv/Scripts/python.exe -m app.reviewer_roles designated-adjudicator@example.com admin
```

Researchers can assign eligible reviewers to their own responses. Reviewers can grade only their assignments. Administrators can resolve disputed reviews in the disagreement queue. A blind assignment requires a reviewer other than the experiment owner. The review response hides provider and model metadata and other scores until submission. A model can identify itself in its response text, so this is metadata blinding. Submitted reviewer records are immutable, and drafts use a revision check to prevent stale saves.

The worker executes Phase 2 responses and Phase 3 evaluations as persisted jobs with leases. A retry appends a new evaluation attempt and retains prior scores, errors, raw output, and exact judge prompt. Each evaluation and review captures the evaluated input at creation. Analytics exclude old scores if a Phase 2 retry replaces the response text. The same reviewer can be reassigned to a revised response with the same rubric. An adjudication applies to the exact submitted review set that it considered. The audit trail records rubric creation, queueing and retry, review changes, adjudication, error classification, snapshots, and reports.

## Demonstration scenario

Use an isolated local project database. Register an owner and two separate users, assign reviewer roles, and give the intended adjudicator an administrator role.

1. In **Experiment Laboratory** select the built-in **PP attachment cases** dataset. Add the **LinguaLens reference · Demo** and **LinguaLens simplified baseline · Demo** profiles and use two repetitions. Name the experiment and start it. Ten items × two profiles × two trials yields 40 stored demo trials. The baseline retains the first ambiguity parse, skips recursion expansion or movement analysis, or applies a phonological substitution without conditioning. Its outputs are authored transformations for demonstration.
2. In **Evaluation Center → Rubric versions**, save a rubric named *Demonstration reference checks*. Assign 70% correctness, 20% structural validity, and 10% completeness. Set analysis and explanation quality to zero for this deterministic demonstration.
3. In **Automated evaluation**, choose the experiment and rubric, select eligible responses from both pages, and queue evaluation. Inspect the agreement with reference fields and the annotations for missing interpretations. Open a stored evaluation and retry it to demonstrate attempt history.
4. Assign the same response to both reviewers under the same rubric. In separate browser sessions, open **Human review → Assigned to me**. Save a draft, submit scores and a verdict, then repeat with the second reviewer. Intentional disagreement illustrates the workflow. For a real study, reviewers grade independently. Open **Disagreements** from the owner or administrator account, inspect votes and score range, and record adjudication with a justification.
5. In **Model Comparison**, select **Curated demonstrations**, the saved rubric, and the experiment. Compare the two profiles and open a shared item in the side-by-side explorer. The leaderboard uses the same cohort rules and suppresses ranks when the protocol or scoring coverage differs.
6. In **Consistency Laboratory**, apply the same filters, select a repeated group, and inspect pair denominators, the timeline, variance, and the canonical structure matrix. Save the cohort snapshot. In **Research Analytics**, inspect sample counts, score distribution, errors, reviewer agreement, and confidence-interval availability.
7. In **Research Reports**, choose the experiment, method, rubric, and **Curated demonstrations**. Generate a report, open its preview, then export PDF, CSV, and JSON. The report cover identifies the demo source. Live research views and leaderboard use a separate population.

For AI-assisted evaluation, configure a live provider from **Settings → AI Model Configuration** and select a judge distinct from the evaluated model. The judge receives the stored stimulus, reference material, response text, and rubric. It returns criterion scores or null, evidence, a brief linguistic justification, errors, an assessment, and confidence. The exact prompt, judge configuration, judge prompt version, raw output, and usage are retained. Treat the result as a fallible second assessment. The same rubric version can receive separate deterministic, judge, and human records.

## Score and agreement definitions

- **Weighted score.** Each criterion is on a 0–100 scale. The weighted total is `sum(weight_i * criterion_i / 100)`. Default weights are 40% correctness, 20% analysis quality, 15% explanation quality, 15% structural validity, and 10% completeness. If a positively weighted criterion is unavailable, the total stays unavailable. Existing criterion storage uses the equivalent 0–1 scale.
- **Deterministic checks.** Correctness equals 100 times the fraction of executed reference or formal checks passed. Stored reference fields can specify ambiguity interpretations and attachment labels, recursion type and segment, movement constituent and positions, or phonological input, output, and environment. Those comparisons use explicit reference fields. Supported phonology substitutions can be tested on held-out pairs whose underlying forms were absent from the stimulus. Tree checks measure structural constraints. An affirmative deterministic verdict requires matching checked evidence and a structurally valid response. Explanatory quality, meaning equivalence, and unconstrained novel expansions require a judge or expert.
- **Human and consensus evaluation.** Human scores remain separate per reviewer. The mean uses submitted weighted scores. Score disagreement is maximum minus minimum. Majority votes use decisive submissions, with at least two decisive votes required to publish a consensus verdict. Conflicting binary votes or a score range of at least 20 points are disputed until adjudication. An adjudication records a categorical override and its justification without modifying the original grades.
- **Agreement.** Percentage agreement is 100 times the fraction of comparable reviewer pairs in agreement. Missing and uncertain ratings are excluded. Cohen’s kappa requires exactly the same two eligible reviewers across at least two observations. Fleiss’ kappa requires a fixed count of at least three eligible ratings per observation. Both use `(P_observed - P_expected) / (1 - P_expected)`; undefined or unsuitable cohorts stay unavailable.
- **Consistency.** Repeat groups share experiment, model, reported model version, item, exact prompt, prompt version, parameters, and planned repetition count. Classification compares the task label or rule fields. Structure compares canonical tree or literal-rule signatures, normalizing movement co-index numbering and ignoring tree node IDs. Exact agreement compares full response text. Verdict agreement uses decisive verdicts only. Score variability and verdict agreement require a common scoring configuration within the repeat group. For each measure, agreement is matching pairs divided by eligible pairs. The UI displays denominators and preserves missing values in matrices. Trial variance and standard deviation are sample statistics using denominator `n - 1`.
- **Optional semantic similarity.** Set `SEMANTIC_MODEL` to an installed Ollama embedding model on the server configured by `OLLAMA_HOST`. With one matched group selected, explicitly request a similarity snapshot. Cosine similarity is the dot product of unit-normalized embeddings. No universal threshold or correctness claim is applied.
- **Comparable performance.** Ranks require matching dataset versions, stimuli, exact prompts and prompt versions, model parameters, trial counts, evaluation method, rubric version, and applicable judge or reviewer configuration. A single recorded model version per identifier is required when the provider reports version changes. All compared trials require weighted scores and the configured minimum distinct matched stimuli. Paired comparisons use the matched subset and average differences within stimuli before combining them.
- **Statistics.** Sample means, medians, sample variance, and sample standard deviation use available observations. The two-sided 95% interval is the 2.5th and 97.5th percentiles of 1,200 resampled independent stimulus means. Repeats collapse within stimulus before resampling. Paired intervals resample within-stimulus differences. At least eight varying stimulus values are required. Missing scores and undecided verdicts are excluded from their relevant denominators. Treat the assumption of independent stimuli as part of the analysis design.

The original paper used standardized prompts and independent human grades. Versioned weighted rubrics, judge assessments, paired comparisons, report exports, and the leaderboard are LinguaLens extensions. [IEEE publication](https://doi.org/10.1109/TAI.2025.3575745) · [Research manuscript](https://arxiv.org/abs/2305.00948)

Run the existing backend and frontend checks, followed by `npm run test:browser` for the Phase 2 workflow. For the Phase 3 browser scenario, use a separate API database with `phase3-browser` in its path or database name. Set `RESEARCH_EVALUATION_TEST_DATABASE` to that same database URL for the browser process, then run `npm run test:evaluation`. It provisions roles only for newly registered test accounts. If needed, set `RESEARCH_TEST_PYTHON` to the backend Python executable, `RESEARCH_BROWSER_CHANNEL=msedge` to use installed Edge, and `RESEARCH_SCREENSHOTS_DIR` to capture the browser views and demo PDF.

The tests use simulated live judge replies. Hosted inference and an Ollama embedding endpoint require separate credentialed or local model verification. Report exports render from frozen observations and include their methodology, missing data, and relevant definitions. The Docker image installs the DejaVu font family for PDF text.

Interactive analysis accepts up to 2,000 stored responses per cohort and 12 models per comparison. Use the experiment, dataset, model, or date filters to narrow larger collections.
