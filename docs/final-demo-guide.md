# Faculty demonstration

Use an isolated workspace and an up-to-date migrated database. Set up the presenter, two reviewers, and an administrator. The recommended run uses authored, clearly labeled profiles and makes zero external inference calls.

| Step | Demonstration |
| --- | --- |
| 1 | Open the landing page and explain the behavioral research question. Open **Research Showcase** for the workflow. |
| 2 | Sign into **My workspace** and explain why the live dashboard may be empty. |
| 3 | Open **Ambiguity Analysis**, use the first built-in item, and run the reference demo model. |
| 4 | Compare VP and NP attachment trees. Select a node, collapse a branch, pan, zoom, and export SVG or PNG. |
| 5 | Open the recursion and movement analyzers. Show the new recursive layer and the co-indexed movement trace. |
| 6 | Open phonology and show the formal rule, the unchanged control and a prediction on a new phone string. |
| 7 | Return to **Research Showcase** and review the featured experiment. The preset selects two curated models, ten attachment items and two repeats. Start the 40 stored trials. |
| 8 | Create a rubric with 70% correctness, 20% structural validity, and 10% completeness. Queue deterministic grading for both trial pages. Submit independent blind reviews through separate sessions and inspect consensus. |
| 9 | In Model Comparison, set **Curated demonstrations**, choose the experiment and saved rubric, and open a shared item. Explain why matched conditions are required. |
| 10 | Inspect a repeat group, then open analytics. Compare agreement with correctness and show the available denominators. |
| 11 | Generate a comparison report for the same cohort. Open PDF and download CSV and JSON. Confirm their demo provenance. |
| 12 | Close with the website's **Research conclusions and limitations** section. Discuss independent annotation, unseen stimuli and external provider verification. |

A fully rehearsed path can start from an existing settled demo record. Keep a fresh run available to show the backend and database actually record each step. For optional live generation, use one configured test model with a limited provider budget and confirm a successful trial before the presentation.
