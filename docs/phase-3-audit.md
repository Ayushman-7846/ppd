The 16 November 2026 audit used isolated SQLite and PostgreSQL databases and two headless Edge browser suites. Credential-free model trials were generated by the app's curated demonstration profiles. Provider and embedding contract tests used simulated responses.

## Reproduced defects and corrections

- Invalid trees used to discard several reference comparisons. The evaluator now retains those checks, rejects identical ambiguity tree topology, and withholds an affirmative verdict when structural validation fails. Held-out phonology checks count each unseen underlying form once and disclose conflicting reference forms.
- Reviews were unique for the entire lifetime of a response ID. The revised uniqueness rule applies per response text and rubric. A decision now applies to its exact submitted review set. Changing outputs cannot make archived error annotations or comparison grades appear beside a different response.
- Model-version changes could enter repeated-run groups or paired estimates. The grouping and comparison checks now account for the versions the provider reports. Reordering the same observations no longer changes the seeded bootstrap interval.
- Missing criteria were drawn at the center of the radar chart by the chart library. Missing error coverage appeared as zero, and some paginated lists estimated a total by adding an assumed next row. Missing results now remain unavailable and uncounted lists show only their page number.
- Non-disputed rows could consume the disagreement page before filtering. An unfiltered live dashboard over the calculation limit could fail to render. Both now retain access to the relevant stored records and counts.
- Empty report cohorts could be exported as recorded data. Report creation now requires matching responses, while missing scores remain exportable for real cohorts. PDFs identify the tasks actually included and distinguish percent correct among decisive verdicts from the number of decisive verdicts.

## Demonstration values and source boundaries

The browser report covered ten authored ambiguity stimuli, two demo profiles, and two repeats per stimulus. The reference profile scored 100 on each of 20 trials and the simplified baseline scored 30 on each of 20 trials under the demonstration rubric. The pooled stimulus mean was 65, and the mean paired difference was 70 points. There was no bootstrap interval because the stimulus-level values had zero variation. All four repeat-agreement summaries were 100% across the 20 eligible groups. These values characterize the authored fixture.

`landing.tsx` embeds an explicitly labeled synthetic chart. The guest and expandable legacy views in `dashboard.tsx`, `research-dashboard.tsx`, and `study-workspace.tsx` show the Phase 1 fixture with a synthetic badge. `model-chart.tsx` labels its accessible synthetic score table. Phase 3 computes the curated demonstration population from persisted trial and grade records and selects live records separately by default.

## Reproduction and remaining verification

- `python -m pytest -q` passed 40 tests in the backend virtual environment. Starlette emitted its existing `httpx` test-client deprecation warning.
- `npm test`, `npm run check`, and `npm run build` passed. Both Playwright suites passed against the built frontend, an isolated database, and the running API and worker. See [browser setup](phase-3.md#files-and-verification).
- Live inference and judging require a configured model identifier and the appropriate credential among `OPENAI_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, and `OPENROUTER_API_KEY`. Enable account-managed encrypted credentials with `CREDENTIAL_KEY` if entering a key through Settings. Use a judge model distinct from the model being evaluated. External judge quality requires a calibrated human-graded cohort.
- Live Ollama verification requires a running endpoint at `OLLAMA_HOST` and an installed model. Semantic similarity also requires `SEMANTIC_MODEL` set to an installed embedding model. Docker deployment verification requires Docker with Compose and the project's PostgreSQL configuration.
- Deterministic checks cover recorded reference fields and supported formal operations. Meaning equivalence, explanation quality, and structurally plausible novel analyses still require expert assessment. Metadata blinding cannot hide an identity disclosed in the output text. A provider can omit model version metadata. The analysis cannot detect version drift in that case.
- Percentile intervals assume independent stimuli and provide observational estimates. Existing historical attempts and exports retain their original scoring and statistical versions. Re-evaluate historical responses if results produced by the corrected scorer are required. Older comparison snapshots without an output hash display the archived aggregates. Their response panels show current output on its own. The formulas were cross-checked against [SciPy's percentile and paired bootstrap documentation](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html) and the [statsmodels kappa implementation](https://www.statsmodels.org/stable/_modules/statsmodels/stats/inter_rater.html).
